## Goal
Update bundled config example and PROJECT.md to showcase per-persona routing.

## Context
- Existing `docs/templates/.teddy/config.yaml` shows only global `llm.*` config.
- `docs/project/PROJECT.md` does not document per-persona routing.
- Users need clear examples and documentation to adopt the feature.

## Scenarios
Primary user journeys and happy paths.

> As a new TeDDy user, I want to see realistic per-persona config examples in bundled config and documentation, so I can quickly adopt the feature.

```gherkin
Given I run `teddy init config`
When I inspect `.teddy/config.yaml`
Then I see a commented `agents:` section with realistic persona models
And when I read `docs/project/PROJECT.md`
Then I see a short section explaining per-persona routing
```

## Edge Cases
- If user config exists, `teddy init config` must not overwrite it (existing behavior).
- Only new configs get the `agents:` example block.

## Key Unknowns

**Format:**
- [ ] [Domain] Should we enable `agents.*` by default (not just example)? Design Sensitivity: if yes → require user opt-out; if no → keep commented out.

## Impact
1. `[EXTEND]` `docs/templates/.teddy/config.yaml` — Add `agents:` example block with commented-out realistic persona models.
   - **Design Sensitivity:** If example config is unclear → user confusion about config structure; if example is outdated → users implement wrong schema.
2. `[MIGRATE]` `docs/project/PROJECT.md` — Add section explaining per-persona routing with config example and fallback behavior.
   - **Design Sensitivity:** If documentation is missing → users cannot adopt feature; if documentation is inaccurate → users misconfigure agents.
