## Goal
Enable per-persona LLM model and API key routing by extending the configuration schema and implementing resolution helpers in `IConfigService`/`YamlConfigAdapter`.

## Context
- `IConfigService` contract defines `get_setting`, `set_setting`, `set_env_variable`.
- `YamlConfigAdapter` loads layered YAML config, supports interpolation, and performs surgical file writes.
- Milestone 7 requires adding optional `agents.*` top-level map in config with optional `model` and `api_key` per persona.

## Scenarios
Primary user journeys and happy paths.

> As a TeDDy user, I want to configure different LLM models and API keys for each agent persona in `.teddy/config.yaml`, so I can use cost-effective or specialized models per task.

```gherkin
Given a `.teddy/config.yaml` with `agents.pathfinder.model: "openai/gpt-4o"` and `agents.architect.model: "anthropic/claude-3-5-sonnet"`
When I start a session with the pathfinder agent
Then the system resolves `openai/gpt-4o` as the model
And when I switch to the architect agent
Then the system resolves `anthropic/claude-3-5-sonnet` as the model
```

## Edge Cases
- If `agents.<persona>.model` is absent, the system MUST fall back to `llm.model`.
- If `agents.<persona>.api_key` is absent, the system MUST fall back to `llm.api_key`.
- If both are absent, the session fails at runtime with the same error as today (no valid model).
- Partial config (some personas missing) must not break existing sessions.

## Impact
1. `[EXTEND]` `IConfigService` — Add `get_agent_model(agent_name: str) -> str` and `get_agent_api_key(agent_name: str) -> str`.
   - **Design Sensitivity:** If extension fails → contracts break; if extension succeeds → all callers can adopt new methods incrementally.
2. `[MIGRATE]` `YamlConfigAdapter` — Implement `get_agent_model()` and `get_agent_api_key()` using existing config loading and interpolation.
   - **Design Sensitivity:** If YAML parsing fails → config schema validation; if interpolation fails → fallback to global config.
3. `[MIGRATE]` `PlanningService` — Add `_resolve_agent_model()` and `_resolve_agent_api_key()` helpers that check CLI flag first, then config.
   - **Design Sensitivity:** If CLI flag precedence is removed → loss of user override capability; if config schema changes → resolution logic must adapt.
4. `[PRUNE]` N/A — No obsolete code.

## Implementation Notes
- Resolution hierarchy (highest to lowest priority): CLI flag `--model` → per-persona `agents.<persona>.model` → global `llm.model`.
- API key resolution hierarchy: per-persona `agents.<persona>.api_key` → global `llm.api_key`.
- Interpolation for `${VAR}` tokens must work in all config sections (`llm.*` and `agents.*`).
